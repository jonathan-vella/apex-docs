Use a standalone Well-Architected Framework assessment when you want an evidence-backed review of an existing workload without generating infrastructure code or deploying changes.

One run produces a five-pillar WAF report, an existing-state architecture diagram, a Cost Management report with visual charts, and a prioritized Excel and Markdown action register inside `agent-output/<project>/`.

## Before you start

1. Open your APEX project repository inside its VS Code dev container. If you have not created a project repository yet, complete the [quickstart](/getting-started/quickstart/) first.
2. Choose how APEX should inspect your workload:
   - Use `azure` to inspect live Azure subscriptions with read-only access.
   - Use `iac` to inspect local Bicep, Terraform, `azure.yaml`, and architecture diagrams with no Azure sign-in.
   - Use `combined` to inspect both local files and live Azure state so the report identifies deployment drift.
3. For `azure` or `combined` runs, sign in from the dev container terminal with an account that has read-only access to the target subscriptions, then check your tenant and subscription IDs:

```bash title="Dev container terminal"
az login --tenant <TENANT_ID>
az account list --query "[].{name:name, id:id, tenantId:tenantId}" --output table
```

## Starter prompt

Open VS Code Copilot Chat, select `01-Orchestrator` from the agent picker, copy the prompt below, replace the `{{...}}` placeholders, delete any optional block you do not need, and send it.

```text title="Copilot Chat (select agent: 01-Orchestrator)"
/waf-assess-existing
Project: {{PROJECT_NAME}}
Scenario: {{SCENARIO}}
Source: {{SOURCE}}
Visual charts: true
Action register: true

Azure read scope:
- Tenant ID: {{TENANT_ID}}
- Subscriptions: {{SUBSCRIPTION_IDS}}
- Workload resource groups: {{WORKLOAD_RESOURCE_GROUPS}}
- Shared resource groups: {{SHARED_RESOURCE_GROUPS}}
- Excluded resource groups: {{EXCLUDED_RESOURCE_GROUPS}}
- Allowed read categories: configuration, topology, utilization, operations, recovery, billing, policy
- Guardrails: Read-only access only. Do not read secrets, keys, connection strings, or certificates, and do not modify Azure resources.

IaC and diagrams:
- Paths: {{IAC_AND_DIAGRAM_PATHS}}

Business context:
- Workload summary: {{WORKLOAD_SUMMARY}}
- Availability and recovery targets: {{SLA_RTO_RPO_TARGETS}}
- Compliance and regions: {{COMPLIANCE_AND_REGIONS}}
- Budget and known issues: {{BUDGET_AND_KNOWN_ISSUES}}
```

### Prompt variables

| Variable | Valid values and guidance | Example |
| --- | --- | --- |
| `{{PROJECT_NAME}}` | Lowercase kebab-case folder name created under `agent-output/`. | `claims-platform-waf` |
| `{{SCENARIO}}` | `requirements_led` scores the workload against your business goals and targets. `evidence_only` skips the business interview and assesses only observed code or Azure state. | `requirements_led` |
| `{{SOURCE}}` | `azure` for live Azure subscriptions, `iac` for repository files only, or `combined` for both. Delete the `Azure read scope` block when using `iac`. Delete `IaC and diagrams` when using `azure`. | `azure` |
| `{{TENANT_ID}}` | Microsoft Entra ID tenant GUID for live Azure reads. Run `az account show --query tenantId -o tsv` to find it. | `00000000-0000-0000-0000-000000000000` |
| `{{SUBSCRIPTION_IDS}}` | One or more subscription GUIDs. Add a short label after each GUID when assessing multiple subscriptions. | `11111111-1111-1111-1111-111111111111 (prod), 22222222-2222-2222-2222-222222222222 (hub)` |
| `{{WORKLOAD_RESOURCE_GROUPS}}` | `all` to assess every resource group in the listed subscriptions, or specific `/subscriptions/<id>/resourceGroups/<name>` paths that belong to the application. | `rg-claims-app, rg-claims-sql` |
| `{{SHARED_RESOURCE_GROUPS}}` | Shared hub, firewall, or management resource groups whose costs and controls support multiple workloads, or `none`. | `rg-hub-network` |
| `{{EXCLUDED_RESOURCE_GROUPS}}` | Unrelated or sandbox resource groups in the same subscriptions to exclude from workload attribution, or `none`. | `rg-sandbox-old` |
| `{{IAC_AND_DIAGRAM_PATHS}}` | Repository-relative paths to Bicep, Terraform, `azure.yaml`, or diagram files for `iac` and `combined` runs. | `infra/bicep/claims/, docs/claims-topology.png` |
| `{{WORKLOAD_SUMMARY}}` | One or two sentences describing what the workload does and who uses it. Delete the entire `Business context` block when `Scenario` is `evidence_only`. | `B2B insurance claims portal and SQL backend` |
| `{{SLA_RTO_RPO_TARGETS}}` | Target uptime, recovery time objective, and recovery point objective. Write `unknown` if not defined yet. | `99.95% SLA, RTO 1 hour, RPO 15 minutes` |
| `{{COMPLIANCE_AND_REGIONS}}` | Regulatory frameworks and required Azure regions, or `unknown`. | `ISO 27001, EU data residency in swedencentral` |
| `{{BUDGET_AND_KNOWN_ISSUES}}` | Monthly budget target and known operational pain points, or `unknown`. | `USD 4,000/month target; SQL latency spikes during peak uploads` |

:::note[Unknown targets and static files]
Write `unknown` for any business target, budget, or recovery metric your team has not established yet. APEX records missing targets and unverifiable runtime settings as `unknown` or `Not assessed` instead of guessing values or assuming compliance.
:::

## What happens after you send the prompt

<Steps>
1. **Confirm scope.** If your prompt leaves any scope detail open, `01-Orchestrator` displays one confirmation form before reading files or querying Azure. When your prompt already specifies the scenario, source, and exact boundaries, `01-Orchestrator` records your scope receipt and writes `01-assessment-brief.md`.

2. **Answer missing business questions for `requirements_led` runs.** When `Scenario` is `requirements_led`, `02-Requirements` reuses everything in your prompt, asks only about missing business context, and writes `01-requirements.md`. It skips greenfield SKU and pipeline setup menus. In `evidence_only` mode, this step does not run.

3. **Wait while APEX collects evidence, builds reports, and runs independent reviews.** Within your approved scope, `01-Orchestrator` coordinates the full pipeline without stopping for intermediate gates:
   - Collects read-only inventory, resource configurations, 7-day metric summaries, policy assignments, and Cost Management history. Redacts secrets and tag values before saving evidence.
   - Scores all five WAF pillars in `03-Architect`, writes the WAF and Cost Management reports, renders SVG and PNG WAF and cost charts, and exports the Markdown and Excel action register.
   - Renders editable SVG and 4K PNG existing-state architecture diagrams in `04-Design`.
   - Runs two independent `challenger-review-subagent` checks for WAF quality and cost feasibility, then repairs owned findings within the review budget.

4. **Accept or revise the completed bundle.** `01-Orchestrator` presents one final prompt where you choose **Accept assessment bundle**, **Revise reports**, or **Stop without accepting**.
</Steps>

## Generated files

Every deliverable is saved under `agent-output/<project>/`:

| File | When generated | What to open it for |
| --- | --- | --- |
| `README.md` | Always | Executive summary, status table, and links to every report, chart, diagram, and review record |
| `02-architecture-assessment.md` and `assets/02-waf-posture.svg` | Always | Five-pillar WAF posture, inline posture chart, control coverage, and prioritized findings |
| `assets/03-des-diagram.svg` and `assets/03-des-diagram.png` | Always | Editable SVG and 4K PNG architecture diagrams of the existing workload, plus reproducible Python source in `assets/03-des-diagram.py` |
| `03-cost-management-report.md`, `assets/03-cost-trends.svg`, and `assets/03-cost-drivers.svg` | Always | Previous-month, preceding-month, month-to-date, and forecast Azure spend with inline trend and driver charts, or labelled retail estimates for `iac` runs |
| `04-assessment-action-register.md` and `assets/04-assessment-action-register.xlsx` | Automatic for `azure` and `combined`; opt-in for `iac` | Prioritized remediation register with effort, recommended windows, and three Excel worksheets: `Action Register`, `Financial Summary`, and `Basis & Evidence` |
| `01-assessment-brief.md` and `01-requirements.md` | Brief always; requirements for `requirements_led` | Authorized read boundaries, reporting periods, and captured business targets |
| `contracts/*.json` and `reviews/challenge-findings-*.json` | Always | Machine-verified evidence, normalized cost data, action-register source, and independent review receipts |

## Resume an interrupted assessment

If your chat session closes or pauses before final acceptance, open a new Copilot Chat, select `01-Orchestrator`, and send:

```text title="Copilot Chat (select agent: 01-Orchestrator)"
resume {{PROJECT_NAME}}
```

`01-Orchestrator` reads the recorded state in `apex-recall` and continues from the active stage without repeating answered questions.

## When to use the delivery workflow instead

Accepting a standalone assessment marks the project complete and never triggers Governance, IaC planning, code generation, or deployment automatically.

| Need | What to run |
| --- | --- |
| Review an existing workload and produce WAF, diagram, cost, and action-register reports only | Select `01-Orchestrator` and run `/waf-assess-existing` using the starter prompt on this page. |
| Generate Bicep or Terraform and deploy new or remediated Azure infrastructure | Run the standard [delivery workflow](/concepts/workflow/) from [Step 1](/concepts/workflow/step-1/) through [Step 6](/concepts/workflow/step-6/). If you already accepted a standalone assessment, reference its `02-architecture-assessment.md` and `04-assessment-action-register.md` when starting the delivery project. |
