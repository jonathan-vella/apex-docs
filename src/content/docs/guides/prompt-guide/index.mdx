## Quick reference

### Agents

Use the [current roster](/concepts/workflow/#core-agents-by-workflow-step).
Orchestrator recommends handoffs; the owner selects main agents.
One planner handles both tracks. CodeGen and Deploy have separate Bicep and
Terraform agents. Challenger is also human-selected.

### Skills

Skills provide reusable instructions. Their flags control automatic selection and
slash-menu visibility; they do not grant tools or permissions. Consult the pinned
[Explorer](/reference/architecture-explorer/) and your checkout's `SKILL.md` files.

Published site writing belongs to apex-docs and its checked-in `unslop` skill.
The historical product `apex-docs-writer` is retired.

### Subagents

Allowed parents call bounded helpers for pricing, validation, or previews.
A helper's result is evidence to evaluate, not approval to continue automatically.
See the [helper reference](/reference/prompts/skills-subagents/#subagents).

### Prompt files

Local `.prompt.md` files adapt shared procedures to VS Code. Check configured
discovery locations and the actual prompt file. Attaching text does not select
its intended main agent automatically.

Host entries are separate manual skills. Select the owner first and verify runtime
support. Static discovery tests cannot establish model entitlement or successful
execution in another client.

#### Core workflow prompts

Use [workflow prompts](/reference/prompts/workflow-prompts/) for current examples.
For resume, the Local adapter is `/apex-resume-workflow`; the Host entry is
`apex-host-workflow-start` with an explicit `resume` operation.

#### Utility prompts

Use the [repository prompt reference](/reference/prompts/repository-prompts/) for
commit and debug-log operations. These are separate from workflow start/resume.
Retired docs-gardening adapters and branch-specific Sensei tooling are not normal
main-branch setup requirements.
